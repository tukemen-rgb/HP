# 自動対応バックログ

公開手前まで、人の判断を待たずに進められる作業のリストです。
ループ実行時は、上から未着手のものを1件取って進め、完了したらチェックを入れます。

**ここに入れてよいもの**：判断が要らず、間違えても戻せる作業。
**入れてはいけないもの**：ドメイン取得、商標、登記、SNS開設、料金の発生する契約、
外部への公開・送信。これらは `launch-checklist.md` 側で人が扱います。

進め方の決まり：
- 1回のループで扱うのは1〜2件まで。まとめてやらない
- 作業後は必ず `npm run verify` を通す
- 通ったらコミットしてプッシュ。通らなければ直すか、元に戻す
- 判断が要ると分かった時点で止めて、その項目に「要確認」と書いて次へ

## 未着手

- [ ] **ページ別の OG 画像**
  現在は全ページ共通。ページ名を入れた版を生成する仕組みを
  `tools/build-og.mjs` に追加し、各ページの `og:image` を差し替える。

- [ ] **アクセシビリティの実測**
  文字色と背景のコントラスト比を全ページで測り、WCAG AA（4.5:1、大きな文字は3:1）を
  下回る箇所を洗い出して調整する。測定は `tools/visual.mjs` に追加。

- [ ] **表示速度の調整**
  Webフォントの `preload` 追加、フォント読み込み中のレイアウト移動（CLS）対策、
  OG画像など大きな画像の遅延読み込み。

- [ ] **構造化データの拡充**
  各ページに `BreadcrumbList`、トップに `WebSite` を追加する。

- [ ] **sitemap の lastmod 自動更新**
  各 HTML の更新日時から `sitemap.xml` の `lastmod` を書き換えるスクリプトを追加し、
  `npm run verify` に組み込む。

- [ ] **ホスティング設定のひな形**
  Cloudflare Pages / Netlify / Apache 向けのセキュリティヘッダ設定
  （`_headers`、`netlify.toml`、`.htaccess`）をコメント付きで用意する。
  適用は公開先が決まってから。

- [ ] **お知らせの個別ページ**
  記事が増えたとき用に、詳細ページの雛形を1枚用意する。
  一覧の `div.news-item` を `a.news-item` に切り替えられる形にしておく。
